# 브동산 — 베트남 호치민 이야기(호치민 라이프 브이로그) 작성 절차

청약·분양/브랜드이야기와는 다른 새 콘텐츠 도메인. Paul(주재원 본인)의 실제 호치민 생활을 사진과 함께 기록하는 시리즈. 카테고리명 "베트남 호치민 이야기", 넘버링 "베트남 호치민 이야기 No.N", 사이트 경로 `vietnam-story.html`(카테고리 페이지), `posts-data.js`의 `category: "vietnam"`.

## 0. 작성자 아이덴티티
이 카테고리는 **"서당댁"**(Paul의 배우자) 목소리로 쓴다. 아바타는 다른 모든 콘텐츠와 동일하게 "브" 원형을 유지하고, byline 작성자명만 "서당댁"으로 표기한다. 상세 규칙은 `beodongsan-author-identity` 스킬 참고.

## 1. 소재 확보
- Paul이 실제 겪은 순간(출퇴근길, 동네 산책 등)을 채팅에 사진으로 첨부받아 사용한다 — 제3자 이미지를 다운로드하거나 생성하지 않는다.
- 사진에 촬영시각 EXIF가 없는 경우가 흔하다(`DateTimeOriginal` 태그 자체가 없음, 파일 mtime도 업로드 시각이라 무의미). 이 경우 **Paul이 업로드한 순서(배치 순서)를 촬영 순서의 대리 지표로 신뢰**한다 — 여러 장을 순차적으로 나눠 올리는 것 자체가 실제 동선을 따라간다는 뜻이기 때문.
- 필요하면 PIL로 라벨이 찍힌 연락표(contact sheet, 여러 장을 격자로 모은 썸네일 이미지 1장)를 만들어 파일명↔장면 매칭을 눈으로 재확인한다 — 특히 장수가 많을 때(20장 이상) 기억에만 의존해 매칭하지 않는다.

## 2. 사진 선별과 배치
- **전체 사진을 다 쓸 필요 없다.** 서사 흐름(기승전결)에 맞는 핵심 장면 위주로 절반 이하로 추려도 된다(예: 37장 중 14장).
- **세로형(portrait) 사진이 대부분이거나 전부일 때, 억지로 가로 비율로 크롭하지 않는다.** 대신 두 장씩 짝지어 나란히 배치한다:
  ```css
  .photo-pair{ display:grid; grid-template-columns:1fr 1fr; gap:8px; margin:22px 0 8px; }
  .photo-pair img{ width:100%; height:100%; aspect-ratio:3/4; object-fit:cover; display:block; border:1px solid var(--hair); }
  .photo-pair .cap{ grid-column:1 / -1; font-size:13px; color:var(--ink-faint); margin-top:2px; }
  ```
  캡션 하나는 페어 전체 아래 "왼쪽부터 — A / B" 형식으로 단다.
- **표지(cover) 이미지는 세로 원본 비율 그대로 쓴다** — 강제로 잘라서 가로로 만들지 않는다(`.cover img{ width:100%; height:auto; display:block; }`). 표지는 그 회차를 상징할 수 있는 사진(예: 노선도, 상징적인 장면)으로 고른다. 표지를 나중에 다른 사진으로 교체할 수 있으므로, 본문 문장에서 "표지 사진이 바로 이거다" 식으로 특정 사진을 지시하는 서술은 피한다 — 표지가 바뀌면 문장이 어색해진다.
- 이미지 압축·base64 임베딩 절차는 `beodongsan-brand-post` 스킬의 "1. 이미지 삽입 기술 절차"와 동일(리사이즈 900px 안팎, JPEG quality 76~85, 앵커 치환, tag-balance 검증).

## 3. 말투 (서당댁 보이스) — 표준 "브동산 문체"와 다름, 2026.09.30부터 더 담백·차분하게
- 청약·분양/브랜드이야기의 격식체·평서형 에세이 톤("~다/~였다/~이다")을 쓰지 않는다.
- 대신 **친근한 반말·해요체**를 쓴다: ~더라구요, ~했어요, ~거든요, ~하더라고요 같은 구어체 종결어미.
- **(2026.09.30 추가) 톤은 담백하고 차분하게 — 감정을 과장하거나 반응을 부풀리는 표현을 쓰지 않는다.** "완전", "진짜", "정말", "너무" 같은 강조 부사로 감탄을 증폭시키지 말고, 있었던 일을 담담하게 서술한다. 구체적으로:
  - **ㅋㅋㅋ 등 웃음 표현은 쓰지 않는다.** 유머러스한 순간이어도 "~하는 눈치였어요", "~했나 봐요" 처럼 차분한 서술로 대신한다.
  - **과장된 반응·비유를 피한다.** "완전 신세계다", "정신이 하나도 없다", "진짜 주인공" 같은 표현 대신 "확실히 다르다", "꽤 복잡해 보인다", "가장 먼저 눈에 들어온다"처럼 절제된 표현을 쓴다.
  - **놀람·감탄의 강도를 낮춘다.** "신기하더라구요", "완전히 다른" 같은 표현은 "새삼스럽더라구요", "풍경이 달라진다" 정도로 톤다운한다.
  - 아래는 실제로 다듬은 예시(2026.09.30, "타오디엔에서 투티엠까지" No.1 톤 조정):
    - "또 완전히 다른 풍경이래요 ... 사진만 봐도 정신이 하나도 없어요. 호치민 출근길 진짜 주인공은 이 오토바이 물결 아닌가 싶어요" → "풍경이 확 달라져요 ... 사진만 봐도 꽤 복잡해 보여요. 호치민 출근길에서 가장 먼저 눈에 들어오는 게 이 오토바이 물결이 아닐까 싶어요"
    - "아직도 신기하다고 하더라구요" → "아직 좀 낯설다고 하더라구요"
    - "'이제 이게 훨씬 편하다'고 은근 뿌듯해하는 걸 보니 웃겼어요 ㅋㅋㅋ" → "'이제 이게 훨씬 편하다'며 은근 뿌듯해하는 눈치였어요."
    - "완전 신세계라고 하더라구요" → "확실히 다르다고 하더라구요"
    - "한 번의 출근길에 이렇게 다른 장면이 다 들어있다니 신기하더라구요" → "한 번의 출근길에 이렇게 다른 장면이 다 들어있다는 게 새삼스럽더라구요"
  - **마무리(총평)에서 과장된 결론을 내리지 않는다.** "이게 호치민에서 제일 마음에 드는 출근길이래요", "한 번의 출근길에 이렇게 다른 장면이 다 들어있다니 새삼스럽더라구요" 처럼 극적인 총평·최상급 표현으로 문단을 맺지 말 것. 대신 **이 회차를 왜 썼는지 소박하고 구체적인 이유**로 마무리한다 — 예: "베트남에서도 한국처럼 지하철 출퇴근이 가능하다는 게 저희한테는 아직 신기해서예요. 평소엔 그랩이나 차로만 다니다가, 가끔 이렇게 메트로를 타면 걷는 구간도 생기고 운동도 되고 나름 괜찮다고 신랑이 그러더라구요." 처럼, 소감을 부풀리지 않고 실제 작은 이유(신기함·소소한 장점)로 담백하게 맺는다.
  - 이 톤다운은 해요체·구어체 종결어미 자체를 없애라는 게 아니다 — 말투(반말/해요체)는 그대로 유지하되, 감정의 진폭만 줄이는 것. 담백함이 지나쳐 딱딱한 격식체(청약 포스팅 톤)로 넘어가지 않도록 주의한다.
- **화자가 "배우자"라는 사실을 대놓고 선언하지 않는다.** "저는 아내예요", "저는 브동산 아내입니다" 같은 정체성 선언 문장을 쓰지 않는다. 대신 "신랑이 찍어온 사진을 제가 정리해봤어요" 같은 자연스러운 서술로만 암시한다 — 읽다 보면 배우자가 썼다는 게 느껴지되, 굳이 명시하지는 않는 방식.
- **제목은 담백하게, "오글거리는" 컨셉(예: "~훔쳐봤어요", 남편 서사를 과하게 강조하는 표현)을 피한다.** 실제 경로·행동 중심으로 짓는다 (예: "타오디엔에서 투티엠까지 — 메트로로 가본 주재원 출근길").
- 도입부에 "베트남 호치민 이야기"를 시작한다는 안내와 회차 번호("No.N")를 자연스럽게 포함한다.
- 마무리는 "총평" 섹션으로 소감을 정리하고, 다음 편을 짧게 예고한다.

## 4. 참고할 실제 문체 샘플
Paul이 특정 블로그 글(예: 티스토리)을 참고 샘플로 링크해줄 때가 있다 — 그 글의 말투(종결어미, 구어체 표현, 문단 길이, 캡션 방식)를 WebFetch로 분석해 이번 회차에 반영한다. 매 회차 참고 링크가 바뀔 수 있으니, 이미 정리된 톤 규칙(위 3번, 특히 담백·차분 톤다운 규칙)을 기본으로 삼되 Paul이 새 샘플을 주면 그에 맞춰 미세 조정한다.

## 5. 디자인/구조 — 기존 브동산 시스템 그대로 재사용
청약·분양/브랜드이야기와 동일한 디자인 시스템(`beodongsan-design-guideline` 참고)을 그대로 쓴다: top-eyebrow(로고+"☰ 목록"), 제목, byline(위 0번), 구분선, 커버, 섹션별 소제목+본문+사진, "다른 브동산 이야기"(`section#related`) 목록, footer. 청약 전용 컴포넌트(스펙표 등)나 브랜드 전용 컴포넌트(`.case`/`.checklist`)는 쓰지 않는다.

- **"☰ 목록" 버튼과 하단 "목록 전체보기" 버튼은 홈이 아니라 실제 카테고리 페이지(`https://brandongsan.com/vietnam-story.html`)로 연결한다.**

## 6. 발행 절차 (신규 카테고리라 처음엔 인프라도 함께 만들어야 함)
1. 카테고리 페이지 `vietnam-story.html`이 아직 없으면 `brand.html`/`realestate.html`과 같은 구조로 새로 만든다(`data-feed data-category="vietnam"`).
2. `index.html`의 내비게이션과 홈 카테고리 타일(`.cat-grid`)에 "호치민이야기" 항목을 추가한다. 타일이 3개 이상이 되면 `styles.css`의 `.cat-grid` 컬럼 수도 함께 조정한다.
3. `posts-data.js`의 `POSTS` 배열에 `category: "vietnam"`으로 항목을 추가한다(스키마는 다른 카테고리와 동일: id/category/tag/title/date/dateLabel/url/preview).
4. `sitemap.xml`에 카테고리 페이지 URL과 새 포스팅 URL을 추가한다.
5. 포스팅 파일 자체는 Artifact로 작성·검증한 뒤, 사이트 배포용으로 `<head>`에 GA 스크립트(`gtag.js`, 측정 ID `G-7TD8E3J131`)와 `google-adsense-account` 메타, `<meta name="description">`을 추가해 다른 실제 라이브 포스팅과 동일한 head 구조로 맞춘다.
6. `beodongsan-deploy-handoff` 절차대로 완성된 파일 전체(신규/수정 파일)를 Paul에게 전달해 클로드 코드로 배포한다.
