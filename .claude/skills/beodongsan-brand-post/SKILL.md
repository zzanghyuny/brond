# 브동산 — 브랜드/공통 콘텐츠 작업 절차

콘텐츠 도메인(부동산이든 브랜드든) 무관하게 공통 적용되는 브랜드 레벨 작업 절차. 상세 배경은 `claude/process-brand.md`, `claude/handoff-master.md`(3번 섹션) 참고. 시각 디자인 규칙(색상/폰트/로고/레이아웃)은 `beodongsan-design-guideline` 스킬을 따로 참고.

## 1. 이미지 삽입 기술 절차 (반드시 이 순서로)
Artifact는 외부 이미지 호스트를 CSP로 차단하므로 **data: URI(base64) 인라인 임베드 필수.**
- base64 텍스트를 대화 컨텍스트나 Edit/Write 툴 파라미터에 절대 직접 붙여넣지 않는다(토큰 폭발 방지).
- 절차: ① bash+PIL로 리사이즈(가로 900~1400px)·압축(사진성 이미지는 JPEG quality 82~85, 색이 단순한 다이어그램/평면도는 PNG + quantize(colors=64~200); 케이스별로 더 작은 쪽 선택) → ② 별도 python 스크립트를 작성해 파일을 읽어 base64 인코딩하고 HTML의 고유 앵커 문자열을 찾아 치환 → ③ 결과 HTML을 tag-balance 검증(div/section/table open/close 개수 비교) → ④ Artifact 재퍼블리시(같은 url 유지).
- **모든 `<img>` 태그에 `style="width:100%;display:block;"`을 반드시 직접 박아넣는다 — 전역 CSS에 기대지 않는다.** Artifact 미리보기 스켈레톤에는 `img{max-width:100%}` 전역 규칙이 있어 인라인 width 없이도 미리보기에서는 정상으로 보이지만, 실제 사이트(`brandongsan.com`)용으로 wrapper를 벗겨내면 이 규칙도 함께 사라져 그 이미지만 원본 픽셀 크기로 삐져나온다. 새 이미지 삽입 스크립트를 짤 때마다 이 스타일이 실제로 붙는지 확인한다.

## 2. 이미지 저작권 정책
원 브랜드/제작사 저작권이 있는 이미지·영상은 직접 다운로드해 게시하지 않는다. 대신 브동산 자체 제작 추상 SVG 커버 + 원본으로 연결되는 출처 링크로 대체한다. 사용 조건이 확실한 이미지(공식 press kit 등)를 Paul이 직접 확보해준 경우만 예외.

## 3. 톤앤매너 (브랜드 보이스)
- "담백하고 과장 없는" 논조 — 좋은 정보만 나열하지 않고 리스크/미달/공급집중 등 불리한 사실도 균형 있게 제공한다.
- 말단 광고(판매원 연락처) 섹션은 반드시 "AD·광고"로 명확히 표기하고, 이름은 "(가상 예시)"임을 명시(실제 인물 사칭 방지).
- **본문 중간(핵심요약·결론 등)에 "투자 조언이 아니다" 류 면책 문구를 넣지 않는다** — 이런 문구는 포스팅 맨 아래 `<footer>`에 이미 한 번 들어가 있으므로 중복 삽입하지 않는다.

### 3-1. 문장 종결 어미 — "브동산 문체" (2026.09.23 확정, 전 포스팅 공통 표준)
**원칙**: 모든 포스팅 본문은 격식체 존댓말("-습니다/-입니다/-합니다/-됩니다")이 아니라 **에세이체 평서형("-다/-였다/-이다/-된다")**으로 쓴다. Paul이 브랜드 언박싱 No.002의 문체("~취급된다", "~정리해본다" 류)를 기준으로 확정한 규칙이며, 이후 모든 신규 포스팅은 처음부터 이 문체로 작성한다.

**적용 범위**: 본문 서술 문장 전체 — 핵심요약, 입지/상품 분석, 결론, 체크리스트 해설은 물론 `<footer>`의 면책 문구 등 말단 boilerplate까지 예외 없이 적용한다(과거 발행분에서 footer만 격식체로 남아있던 사례가 반복 발견됐다).

**전환 규칙**:
- 형용사: "-습니다" → "-다" (예: 어렵습니다→어렵다)
- 동작동사 현재형: "-ㅂ니다/-습니다" → "-ㄴ다/-는다" (예: 나옵니다→나온다, 적용됩니다→적용된다)
- 과거형: "-았/었/였습니다" → "-았/었/였다" (예: 미달됐습니다→미달됐다)
- "명사+입니다": 받침 있으면 → "명사+이다"(예: 기준입니다→기준이다), 받침 없으면 축약된 "명사+다"(예: 결과입니다→결과다), "아닙니다"→"아니다"
- "하다" 동사: 형용사적 용법(예: 곤란하다·동일하다)은 "-하다" 그대로 유지, 동작 용법(예: 산출하다·보정하다)은 "-한다"로 전환
- 존칭 "-시-" + 권유형(예: "확인하시기 바랍니다") → "-시-"를 빼고 자연스러운 에세이체로 재구성(예: "확인해보길 바란다") — "확인하시기 바란다"처럼 존댓말+평서체가 섞인 어색한 표현은 만들지 않는다.

**작업 방법 (재현용)**:
1. Artifact `action:"read"`로 반드시 최신 라이브 버전을 먼저 읽는다(저장된 tool-result 파일을 그대로 재사용하지 않는다 — publish가 거부될 수 있다).
2. 별도 python 스크립트에서 정확한 단어 단위 매핑 딕셔너리(예: `MAP = {"어렵습니다": "어렵다", ...}`)를 만들고 `str.replace()`로 전체 치환한다. base64 이미지 데이터는 A-Za-z0-9+/= 문자만 쓰므로, 전각/한글 단어를 통째로(whole-word) 치환하는 방식은 base64를 손상시키지 않는다 — 별도 스트리핑 없이 그대로 적용 가능.
3. 치환 후 `grep -o "니다"` 등으로 격식체 잔존 여부를 재검색해 누락이 없는지 확인한다.
4. div/section/p/li/table/tr/td 등 태그 개수를 치환 전/후로 비교해 tag-balance를 검증한다.
5. 같은 Artifact url로 재퍼블리시한다.

## 4. 말단 AD 카드 — "광고 신청하기" CTA (모든 포스팅 표준 구성요소, 작성 시 처음부터 포함)
각 포스팅 맨 아래 `section#ad`의 `.sponsor` 카드(가상 예시 상담 카드)와 별개로, 실제 광고주가 신청할 수 있는 진짜 동작하는 CTA를 점선 구분선 아래에 추가한다.
- 구성: 안내 문구("이 자리에 광고를 원하는 부동산·분양 담당자이신가요?") + "광고 신청하기" 버튼(`.btn-outline`, `mailto:0324jhkim@gmail.com?subject=...&body=...` — 단지명/문의칸 미리 채움, URL 인코딩 필요) + 이메일 주소(`<code>`) + "복사" 버튼(`navigator.clipboard.writeText` 우선, 실패 시 숨김 textarea + `execCommand('copy')` 폴백, 성공 시 버튼 텍스트 "복사됨"으로 1.5초간 표시).
- CSS는 기존 흑백 톤(`--ink`/`--hair`/`--ink-faint`)만 사용 — 새 색상 추가 금지.

## 5. 광고 문의 → 입금 → 네임카드 업데이트 파이프라인
1. **자동 답장**은 스케줄 작업(cron, trigger id `trig_01RkYDwNw26T7j9Xo8zkpgXs`)이 이미 처리 중 — 제목에 "광고 문의" 포함된 미답장 스레드에 고정 안내(광고비 2만원, 계좌 하나은행 101-910-47774407 예금주 김장현)를 보내고 Gmail 라벨(`브동산/광고문의-답장완료`)을 붙인다. 문구·금액·계좌는 Paul이 명시적으로 요청하지 않는 한 임의로 바꾸지 않는다.
2. **입금 확인**은 Paul이 대화에서 직접 확인해줘야만 다음 단계로 진행한다 — 자동화가 스스로 판단하지 않는다.
3. **네임카드 업데이트**: Paul이 광고주 이름/연락처를 주면 해당 포스팅의 `.sponsor` 카드를 실제 이름·연락처로 교체하고 "(가상 예시)" 표기를 제거한다. 이미 `brandongsan.com`에 반영된 포스팅이면 `beodongsan-deploy-handoff` 절차로 배포까지 진행한다.

## 6. "브랜드 언박싱" 시리즈
Paul이 브랜드 광고를 공부하며 쌓는 진행형 기록. 청약 포스팅과 동일한 디자인 시스템을 재사용하되, 청약 전용 컴포넌트(스펙 리스트·타입표) 대신 사례별 카드(`.case`)·체크리스트(`.checklist`)를 쓴다. 체크리스트는 단순 감상이 아니라 **"광고를 기획할 때 체크할 질문"(기획자 관점)**으로 작성 — 브동산 자체 콘텐츠 기획에도 쓸 수 있어야 한다.

## 7. 영상 제작 파이프라인
완성된 포스팅 → 롱폼(유튜브, 씬 약 9개) 대본 → 숏폼(쇼츠, 씬 약 5개) 대본 → Paul이 Higgsfield로 실제 영상 제작. 각 씬은 Higgsfield 3계층 구조로 작성한다:
1. **Popcorn keyframe** — 샷/피사체, 카메라 구도, 조명, 배경/환경, 렌즈/필름룩, 무드
2. **Identity** — 캐릭터/얼굴 (현재는 사람 얼굴 없는 모션그래픽 스타일로 의도적으로 회피)
3. **Video prompt** — 오프닝 액션, 카메라 위치/무브먼트, 환경과의 상호작용, 카메라 이펙트, 엔딩 무드
작성 현황은 `claude/posts-brand.md`에서 관리한다.
