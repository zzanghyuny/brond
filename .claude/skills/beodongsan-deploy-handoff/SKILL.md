# 브동산 배포 핸드오프

## 배경
브동산(brandongsan.com)은 프레임워크 없는 정적 HTML 사이트로, GitHub 저장소 `zzanghyuny/brond`(main 브랜치)에 반영되면 Vercel이 자동으로 재배포한다.

콘텐츠 리서치·작성·검증은 "브동산" Claude 프로젝트(디자인 가이드라인·콘텐츠 제작 기준·브동산 모형 산식 등 전체 맥락 보유)에서 진행하고, 실제 GitHub 반영(배포)은 클로드 코드(Claude Code)가 `brond · main` 환경에 연결된 상태에서 담당한다.

Cowork 클라우드 세션(브동산 Claude 프로젝트가 돌아가는 곳) 자체는 보안 프록시 때문에 GitHub에 직접 push할 수 없다 — 이건 그 세션만의 제약이고 클로드 코드에는 해당하지 않는다. 그래서 배포는 항상 사람을 거쳐 클로드 코드로 넘어간다.

## 콘텐츠 방(브동산 Claude 프로젝트) 쪽에서 할 일
새 포스팅이나 사이트 파일 수정이 끝나면:
1. 완성된 파일들(신규/수정 파일 전부, 예: 포스팅 HTML + `posts-data.js` + `sitemap.xml` + 관련 포스팅 갱신이 반영된 기존 포스팅 파일들)을 정리한다.
2. 아래 지시문 템플릿을 이번 작업 내용에 맞게 실제 파일명·경로·커밋 메시지로 채운다.
3. 파일들과 채워진 지시문을 사용자에게 함께 전달하면서, "클로드 코드에서 `brond · main` 환경을 먼저 선택한 뒤 이 파일들을 첨부하고 아래 문구를 그대로 보내면 배포됩니다"라고 안내한다.
4. 클로드 코드에는 콘텐츠를 새로 쓰거나 수정해달라고 시키지 않는다 — 이미 완성된 결과물을 그대로 반영하는 역할만 맡긴다.

### 지시문 템플릿
```
첨부한 파일들을 브동산 사이트 저장소(zzanghyuny/brond, main 브랜치)에 아래 경로 그대로 저장해줘.
기존 파일과 경로가 같으면 그 내용으로 덮어써줘. 저장 후 git add/commit/push까지 진행해서
Vercel에 자동 배포되게 해줘.

- [첨부파일명 1] → [저장소 내 경로, 예: posts/xxx.html]
- [첨부파일명 2] → posts-data.js
- [첨부파일명 3] → sitemap.xml
- [첨부파일명 4] → [갱신된 기존 포스팅 경로]

커밋 메시지: "[예: Add 화서역 호수공원 아너스빌 post to 청약·분양 (No.006)]"
```
(파일 개수·경로·커밋 메시지는 그때그때 실제 작업 내용에 맞춰 채운다.)

## feed.xml 갱신 (RSS) — 새 글을 올릴 때마다
새 포스팅이 `posts-data.js`에 등록되면, 커밋 전에 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-feed.ps1`을 실행해 `feed.xml`(RSS 2.0, 최신 30개)을 다시 만들고 같은 커밋에 포함한다. 수동 편집 금지. 콘텐츠 방에서는 지시문의 파일 목록에 `feed.xml`을 넣을 필요 없이 "posts-data.js 반영 후 scripts/build-feed.ps1 실행해서 feed.xml도 같이 커밋" 한 줄만 덧붙인다. `naver-html/`은 RSS에 넣지 않는다.

## 클로드 코드(배포 담당) 쪽에서 할 일
`brond · main` 환경에 연결된 상태에서 위와 같은 형식의 지시(첨부 파일 + 경로 매핑 + 커밋 메시지)를 받으면:
- 각 첨부 파일을 지정된 경로에 정확히 그대로 저장한다 — 내용을 재작성하거나 수정하지 않는다(이미 완성된 결과물이다).
- 기존 파일이 있으면 덮어쓴다.
- git add, 지정된 커밋 메시지로 commit, main 브랜치로 push까지 진행한다.
- push 즉시 Vercel이 자동 재배포하며, 별도 확인/승인 단계가 없다 — 그러니 경로나 파일명이 지시와 다르거나 애매한 부분이 있으면 임의로 추측해서 진행하지 말고 먼저 확인을 구한다.
- 이 작업의 역할은 "배포"로 한정된다 — 포스팅 내용을 새로 쓰거나 고치거나 요약하지 않는다. 콘텐츠 관련 요청이 들어오면, 그건 브동산 Claude 프로젝트(Cowork)에서 먼저 작업해야 한다고 안내한다.

## 참고
- 대체 경로: 클로드 코드를 쓸 수 없는 상황이면 GitHub 웹 화면에서 수동으로 "Upload files" → 반드시 "Commit changes" 버튼까지 클릭해서 진행한다.
- 사이트 구조·배포 관련 전체 맥락은 브동산 프로젝트의 `claude/it-plan.md` 문서를 참고한다.
