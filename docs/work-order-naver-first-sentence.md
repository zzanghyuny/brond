## 1. 왜 하나

네이버·구글 검색 결과에 보이는 설명문(og:description)은 **본문 첫 줄에서 자동으로 만들어진다**. 지금은 첫 줄이 바이라인이라 검색 결과 설명이 이렇게 나온다.

> 브동산 · 청약 언박싱 No.109 · 2026. 11. 18 (2026.11.19 공고 기준) 1. 결론부터 — 이 단지 예상 프리...

- 날짜와 글 번호가 설명문 앞자리를 차지하고, 핵심 내용(단지명·분양가·예상 프리미엄)은 잘린다.
- 바이라인 날짜(11. 18)와 공고 기준일(11.19)이 어긋나 보인다.

검색 결과 설명에 **단지명·분양가·적정가격·예상 프리미엄**이 바로 보이면 클릭률이 오르고, 검색엔진이 글의 주제를 더 정확히 읽는다.

## 2. 바꿀 내용 (규칙)

1. **본문 맨 첫 문단은 요약문**으로 한다.
   - 한두 문장, 공백 포함 약 80~120자.
   - 들어갈 것: 단지명, 지역, 84㎡ 평균 분양가, 브동산 적정가격, 예상 프리미엄. 필요하면 청약 일정도 넣는다.
   - 문체는 "~입니다/~예요"가 아니라 승인 샘플과 같은 평서형(~다)으로 쓴다. 숫자 표기는 본문과 똑같이 맞춘다.
2. **바이라인은 첫 줄에서 내린다.**
   - "브동산 · 청약 언박싱 No.NNN · 날짜 (공고 기준)"은 요약문 바로 아래에 둔다. 작은 회색 글씨는 그대로다.
   - 날짜는 **발행일 하나만** 쓴다. 공고일은 괄호 안에 "○○.○○ 공고 기준"으로 따로 적는다. 바이라인 날짜와 공고일을 같은 숫자처럼 보이게 쓰지 않는다.
3. 그 아래 순서(1. 결론부터 …)는 바꾸지 않는다.
4. 공고 전 글(분양가 미공개)은 요약문에 적정가격만 넣고 "분양가는 공고 후 업데이트"를 붙인다.

## 3. 예시

**바꾸기 전 (본문 첫 부분)**
```
브동산 · 청약 언박싱 No.109 · 2026. 11. 18 (2026.11.19 공고 기준)

1. 결론부터 — 이 단지 예상 프리미엄은 +5,960만원
```

**바꾼 뒤**
```
고양 행신동 한신더휴 퍼스트원의 84㎡ 평균 분양가는 8.08억원, 브동산 분석 적정가격은 8.68억원으로 예상 프리미엄은 +5,960만원이다. 청약은 11월 30일 특별공급부터다.

브동산 · 청약 언박싱 No.109 · 2026. 11. 19 발행 (11.19 공고 기준)

1. 결론부터 — 이 단지 예상 프리미엄은 +5,960만원
```

요약문 틀 (단지마다 값만 바꿔 쓴다):
> {지역} {단지명}의 84㎡ 평균 분양가는 {분양가}, 브동산 분석 적정가격은 {적정가격}으로 예상 프리미엄은 {±금액}이다. 청약은 {특별공급 날짜} 특별공급부터다.

## 4. 할 일

### A. Claude Code (양식·앞으로 만들 글)
1. 승인 샘플 `docs/naver-sample/gwanggyo-jayeon-centreville-naver.html`과 `docs/naver-sample/README.md`에 위 규칙을 반영한다.
   - 바이라인 위치를 바꾼다.
   - 첫 문단에 요약문을 넣는다.
2. `CLAUDE.md`, `docs/naver-mobile-spec.md`, `docs/handoff-cheongyak-pipeline.md`(6장)에 규칙을 한 줄씩 추가한다.
3. (폰 키트는 2026.11.26 폐지 — 해당 없음)
4. **아직 네이버에 발행하지 않은 글**의 `naver-html/<slug>.html`을 새 순서로 고친다.
   - 발행하지 않은 글은 `posts-manifest.json`에서 `naver_published`가 false인 글이다.
5. 커밋·push하고 수정한 글 목록을 Paul에게 보고한다.

### B. Aside (이미 발행된 글)
1. 네이버 글 수정 화면에서 본문 맨 위 바이라인 줄 **위에** 요약문 한 문단을 넣는다.
   - 요약문은 Claude가 글별로 만들어 준 목록을 그대로 복사한다(→ 5장).
2. 바이라인 날짜가 공고일과 헷갈리게 쓰여 있으면 "발행일 (○○.○○ 공고 기준)" 형태로 고친다.
3. 저장(수정 발행)한다.
4. 우선순위는 최근 글과 청약 일정이 남은 단지부터다.
   - 1순위: 11월 15~19일 발행분(청약 접수 전·진행 중인 단지)
   - 2순위: 나머지 청약 글
   - 브랜드·일반 정보 글은 이번 대상이 아니다.
5. 하루에 수정 발행하는 글 수는 몇 개로 나눈다. 한꺼번에 많이 수정하지 않는다.

## 5. 이미 발행된 글의 요약문 목록
- Claude Code가 `posts-manifest.json`에서 `naver_published: true`인 청약 글을 뽑는다.
- 글마다 3장 틀에 맞춘 요약문을 만들어 이 문서 아래(또는 `docs/work-order-naver-first-sentence-list.md`)에 표로 붙인다.
  - 표 열: 네이버 글 번호 · 제목 · 요약문
- Aside는 그 표를 보고 붙여 넣는다.

## 6. 확인 방법
- 수정한 글을 폰에서 열고, 맨 위에 요약문이 보이는지 확인한다.
- 하루 이틀 뒤 네이버에서 글 제목을 검색한다. 결과 설명문이 요약문으로 바뀌었는지 본다. 검색 반영에는 시간이 걸릴 수 있다.
- Claude Code는 글 페이지(`m.blog.naver.com/bds_unboxing/<글번호>`)의 `og:description` 값이 요약문으로 시작하는지 확인할 수 있다.

## 7. 하지 말 것
- 요약문에 본문과 다른 숫자를 쓰지 않는다. 제목·스탯 박스·본문의 금액과 같아야 한다.
- "무조건", "확정 수익" 같은 단정 표현을 쓰지 않는다. 예상 프리미엄은 브동산 모형 추정치다.
- 요약문 때문에 섹션 순서나 다른 문단을 바꾸지 않는다.
