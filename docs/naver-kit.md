# 네이버 폰 발행 키트 (naver-kit)

폰의 네이버 블로그 앱으로 글을 올릴 때 쓰는 페이지. 앱 에디터는 HTML 통째 붙여넣기·표·외부 이미지 URL을 안정적으로 받지 못해서, `naver-html/<slug>.html`을 **순서대로 복사·저장하는 블록**으로 바꿔 둔다.

## 폰에서 쓰는 법 (아이폰·안드로이드 공통, 4단계)
1. 폰 브라우저에서 `https://www.brandongsan.com/naver-kit/<slug>.html`(목록: `/naver-kit/index.html`)을 연다. 검색엔진에는 노출되지 않는다(noindex, robots 차단).
2. **이미지 전체 사진첩에 저장** 버튼 → 공유창에서 '이미지 저장'(Web Share API). 안 되는 브라우저는 zip이 대신 내려받아진다. 개별 이미지는 칸마다 [이미지 저장]이나 길게 눌러 저장. 파일 이름이 `01-…`, `02-…` 순이라 사진첩에서도 글 순서대로 정렬된다.
3. 네이버 앱 새 글에서 위에서부터 **[복사] → 붙여넣기**(제목·태그는 첫 두 칸). 이미지 자리마다 앱의 사진 버튼으로 **같은 번호의 사진**을 넣는다. 한꺼번에 여러 장을 고를 때는 번호 순서대로 눌러야 그 순서로 들어간다.
4. 맨 아래 체크리스트(카테고리 부동산이야기·대표 이미지·태그)로 마무리하고 발행. 각 칸 완료 체크는 폰에 기억된다.

### 이미지 묶음 (올릴 장수 줄이기)
- 사이에 **짧은 캡션(≤70자)이나 짧은 h3 제목(≤40자)만** 있는 연속 이미지는 세로로 이어 붙인 한 장(`NN-set.jpg`)으로 만든다. 폭 1000px, 조각마다 위에 제목·캡션을 이미지에 직접 새긴다(WQY 폰트 30px 이상), 높이 4500px 넘으면 `set-1/set-2`로 나눈다, JPEG ≤ 800KB.
- 묶인 이미지는 키트 페이지에서 "이미지 01–04 묶음"처럼 표시되고, 새겨진 캡션은 별도 복사 칸이 없다. 사이에 문단이 끼는 이미지(차트 ↔ 본문 문장 등)는 따로 둔다.
- 결과: 글당 11~21장 → 5~13장.

### PC에서 올릴 때
HTML을 통째로 붙여넣으면 이미지가 외부 링크로만 걸려 검색에서 이미지 없는 글처럼 보인다. 같은 `naver-kit/<slug>/` 이미지(또는 zip)를 에디터의 **사진 버튼으로 직접 올리면** 네이버에 올라간 이미지가 되므로, 본문 텍스트만 붙여넣고 이미지는 이 파일들을 순서대로 올리는 방식을 권장한다.

한계: 앱이 붙여넣은 글의 굵게·링크를 일부 지울 수 있다(소제목은 앱에서 굵게/크게 직접 지정). 앱 에디터 동작은 버전마다 달라 실제 폰에서 첫 글로 확인이 필요하다. Web Share로 여러 장을 한 번에 저장하는 동작은 iOS Safari·Android Chrome에서 지원되지만 기기·개수에 따라 거부될 수 있고, 그때는 zip이 대신 내려받아진다.

## 다시 만들기
```bash
python3 scripts/naver_kit.py <slug> [<slug> ...]   # 글 하나 이상
python3 scripts/naver_kit.py --all                  # 발행 전(naver_published=false) 전체
python3 scripts/naver_kit.py --index-only           # 목록 페이지만
```
결과: `naver-kit/<slug>.html`, `naver-kit/<slug>/NN-*.png|jpg`(발행 순서 번호), `naver-kit/<slug>.zip`, `naver-kit/index.html`. 표가 5열 이상이면 경고를 출력한다(폰에서 글씨가 작아짐 — 글에서 4열 이하로 줄이거나 문장을 짧게). `naver-html` 파일은 바꾸지 않는다. 필요: Python(bs4, Pillow), Node Playwright(표·스탯 박스 렌더).
