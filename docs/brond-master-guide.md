## 0. 우리는 누구인가
- 브동산은 **청약·미분양 정보를 '브동산 적정가'로 판정해 주는 부동산 미디어**다. 웹사이트·네이버 블로그·유튜브·네이버 클립에 배포한다.
- 태도: 담백하고 과장 없이, 숫자로. 판단 근거를 밝히고 투자 권유를 하지 않는다.
- 역할: **Paul**(사장, 방향·승인) · **Claude**(조사·작성·제작·사이트 배포·드라이브 전달) · **어사이드(Aside)**(네이버 블로그 발행, 유튜브·클립·인스타 업로드).

## 1. 절대 원칙 (모든 콘텐츠 공통)
1. **숫자는 공식 자료에서만.** 입주자모집공고·청약홈·KB시세·국토부 실거래·법령·보도자료. 확인 못 한 숫자는 "확인하지 못했다"로 쓰거나 뺀다. 지어내지 않는다.
2. **예상 프리미엄 = 브동산 적정가 − 분양가.** 표기는 **금액 먼저, 판정은 괄호**: `예상 프리미엄 +5,960만 (저평가)`. 판정 기준은 분양가 대비 +3% 이상 저평가 / ±3% 미만 적정 / −3% 이하 고평가. 금액은 십만원 단위 반올림(1억 이상은 `+1.74억`).
3. **평당가·㎡당가는 쓰지 않는다.** 같은 크기 타입끼리 총액으로 비교한다(84㎡ 우선, 없으면 59㎡).
4. 과장·수익 약속 문구 금지("돈 버는", "무조건"). 내부 모형 용어(L1~L5, 6-1, 레슨런) 금지. 광고 문의 카드 금지.
5. 사진은 공식 분양 홈페이지(CG 표기)·Pexels·위키미디어 등 출처를 밝힌 것만. 실제 지도 서비스 캡처 대신 브동산 자체 개략도. Google Earth 화면은 출처 표시, 썸네일·표지에는 쓰지 않는다.
6. 문체: 사이트 글은 평서형(~다), 네이버 원고는 존댓말(청약)·해요체(도시이야기).
7. 디자인: **흑백 + 황동 포인트 `#C8A45C`**, 판정색(저평가 녹색·고평가 적색)은 금액·판정에만. 로고는 '브'(굵게)+'동산'(가늘게) 워드마크, 장식 없음.

## 2-1. 교차링크 전략 (2026.11.28 Paul 확정)
**원칙**: 모든 길은 웹사이트로 모인다(애드센스·쿠팡·계산기 수익이 나는 곳). 다만 각 채널 안에서 할 일(클립 → 블로그, 쇼츠 → 긴 영상)을 먼저 하고 마지막에 사이트로 보낸다.

**불이익을 피하는 규칙** (교차링크 자체는 불이익이 없고, 아래를 어기면 노출이 줄어든다)
- 링크는 글·영상당 1~2개. 같은 링크를 본문·댓글마다 반복하지 않는다.
- **네이버 글에 쿠팡 링크 금지**(외부 제휴 링크는 저품질 신호, 수익은 쇼핑커넥트로).
- 사이트 글을 네이버에 그대로 복사하지 않는다(구성 절반 이상 다르게 — 중복 문서로 한쪽이 묻힌다).
- 네이버 도시이야기 글의 유튜브 링크는 불이익이 없다. 글쓰기 창 '링크' 버튼으로 **영상 카드 1개**만 넣는다(블로그 안에서 재생돼 체류시간에도 도움).
- 사이트 글 본문에는 네이버 링크를 넣지 않는다(채널 링크는 홈·소개 바닥에만).

## 4. 청약 언박싱 (가장 많이 만드는 콘텐츠)
**공고 찾기**: 청약홈 APT 분양정보 목록(브라우저 UA로 curl)에서 `scripts/applyhome-processed.json`에 없는 **아파트** 입주자모집공고만. 오피스텔·도생·민간임대·무순위·임의공급은 다루지 않는다(오피스텔은 Paul이 따로 지시할 때만, 그때는 아파트 59㎡ 비교 후 ×0.9). '공고 전' 글이 이미 있으면 새 글 대신 그 글을 공고 기준으로 갱신(드라이브 폴더 끝 ` — 수정 발행`).

**브동산 적정가 모형** (스킬 `beodongsan-realestate-post`):
- 비교단지 2곳은 고정 기준 = **같은 동·생활권 이웃 1 + 가까운 중심권 신축 대단지 1**(연식·규모·브랜드 근접). `scripts/beodongsan/comp_scan.py`로 2016년 이후·500세대 이상을 전수 스캔하고 후보 표(탈락 사유 포함)를 글에 싣는다. 가격이 높거나 낮다는 이유로 고르거나 빼지 않는다. Paul에게 묻지 않고 직접 찾는다.
- 기준가 = 비교단지 같은 타입 KB 일반거래가(없으면 최근 실거래). 평점표 100점(입지 40·브랜드 20·상품성 40) → 평점보정 1±(점수차×0.01, 최대 ±20%) × 연령보정(SITE 준공예정 기준, 서울·수도권·광역시 최대 1.2 / 기타지방 최대 1.3) → 두 보정가격의 평균 = 브동산 적정가.

**사이트 글 배치**: 커버 = 입지 개략도(`chart-map-naver.png`, 한 번만) → 1장 핵심요약(브리프 → 스탯 박스 → 레이더 → 브릿지 → 평점표 → 점수 근거 → 비교단지 후보 표) → 2장 입지 → 3장 상품(공식 조감도, 공급금액, **평면 전 타입**, 청약 일정은 `chart-c-schedule.png` 하나) → 4장 공급 → 5장 결론. 같은 정보는 한 번만. 결론 아래 쿠팡 카드(`scripts/coupang/apply_coupang.py`).
- 등록: `posts-data.js`(제목 형식 `지역 - 단지명 | …, 84㎡ 평균 분양가 X.XX억, 예상 프리미엄 ±N` — 홈 대문·계산기가 이 제목을 읽는다), `posts-manifest.json`, `sitemap.xml`, `feed.xml`, 썸네일 `python3 scripts/build_thumbs.py`.

**네이버 원고** (기준 파일 `naver-html/goyang-hanshin-thehue-firstone.html`, 스킬 `beodongsan-naver-copy`): 굵은 첫 두 문장(검색 미리보기) → 회색 바이라인 → 제목 → 6섹션(1 결론부터: chart-b → 조감도 → 개요 표 / 2 왜 이 가격: 입지 개략도 → 비교단지 → chart-a → 보정 표 / 3 한줄평 / 4 지역 최근 분양 / 5 공식 이미지 **번호 없이** 나열 + 일정 인포그래픽 / 6 결론 + 사이트 링크 + 계산기 링크). **대표사진 = 입지 개략도.** 표는 PNG로(`scripts/naver_tables_to_png.py`), 하단 쇼핑커넥트 칸(`scripts/shopconnect/apply_naver_shop.py`, 글 내용을 보고 상품 3개를 글마다 다르게 — 스킬 `beodongsan-shopconnect`), 모바일 폭(이미지 1000px·글씨 28px+).

**쇼츠 3편** (`scripts/shorts/README.md`, 스킬 `beodongsan-video-team`): ① 시네마틱 분양가 총정리 `make_gen.py`(나레이션 없음, slow + 브릿지) ② 가격 맞히기 `make_quiz.py`(InJoon 남자 나레이션) ③ 1분 총정리 `make_brief.py brief/<키>.json`(현금 → 예상프리미엄 → 입지 → 단지·평면 → 모집공고 유의사항, InJoon +40%). '공고문 속 숨은 한 줄'은 요청 시만. 영상마다 썸네일·제목을 함께 준다.

**카드뉴스**: 1분 총정리와 같은 데이터·순서. 표지에 큰 단지명 + **"이 단지, 적정가는 얼마?"** + "청약 전 이것만 보세요 — 1분 총정리" + 체크리스트 5줄 → 현금 → 예상프리미엄 → 입지 → 단지·평면 → 유의사항(가격 조건 / 주변·단지 안 시설) → 요약·일정·계산기.

기준: `docs/cheongyak-scheduled-run.md`, `docs/handoff-cheongyak-pipeline.md`.

## 5. 미분양 선착순 랭킹 · 줍줍찬스
- 권역: 수도권(1·16일) · 충청(8일) · 부산·울산(12일) · 대구·경북·강원(20일) · 경남·호남·제주(24일). 선착순 확정 = 공식 홈페이지 선착순 표기 또는 최근 1개월 상담사 글 또는 최근 30일 분양 광고. 청약 접수 중·예정, 무순위, 오피스텔·도생 제외.
- 순위 = 예상 프리미엄÷분양가. +5% 초과·−20% 미만은 비교단지부터 다시 본다. 실거주 요건이 좋은 단지는 "실거주자에게 기회"로 긍정 평가하되 숫자는 정직하게. 2회차부터 '지난 회차 대비' 표.
- 산출물: 사이트 글 · 네이버 모바일 원고 · 가로 본편(유튜브 + 네이버 클립 롱폼) + 세로 쇼츠 · 카드뉴스 TOP5 10장(표지 → 읽는 법 → 1~5위 → 지난 회차 대비 → 실거주 체크 → 줍줍찬스 안내).
- **줍줍찬스**(`/jupjup/`): 전국 선착순 단지 목록·단지 페이지. **적정가·예상 프리미엄·비교단지 시세는 코너에 쓰지 않고** 확인된 장점만 긍정 어투로. 모집공고·분양 홈페이지 버튼. 상담사 카드(단지당 3칸, 2주 5만·4주 7만)는 메일 신청 + 계좌이체, **Paul이 입금됐다고 답한 신청만 게재**, 상담사에게 메일 보내지 않음. 예상 프리미엄 −3% 미만 청약 글은 Paul 지시 시에만 내리고 줍줍 페이지로 리다이렉트.
- 기준: `docs/firstcome-runbook.md`, `docs/handoff-firstcome-ranking.md`, `docs/ad-radar.md`, CLAUDE.md 줍줍찬스 섹션.

## 6. 랭킹 쇼츠 · 도시이야기
- **랭킹 쇼츠**: '가장 ○○한 곳' 통계 쇼츠를 하루 3편 묶음으로 미리 만든다(데이터 `scripts/shorts/rank/`, 출처·기준일 명시). 카드뉴스는 반응 좋은 주제 하루 1편: 질문 표지 → 10~4위 목록 → 3·2·1위 한 장씩 → 기준·출처 → "다른 랭킹 보기".
- **도시이야기**: 도시 구조·역사. 제목은 도시 이름으로 시작하는 질문형. 한 도시 = 가로 본편 1 + 쇼츠 2 + 썸네일 3 + 사이트 글 + 네이버 원고(해요체, 사이트와 구성 절반 이상 다르게, '영상으로 보기' 칸에 유튜브 본편 영상 카드 1개). 본편은 유튜브와 같은 날 네이버 클립 롱폼에도. 카드뉴스 10장: 드론 실사 표지 → 숫자로 → 이유 3가지 → 희한한 집 2장(실제 사는 모습·특이한 주거형태 사진) → 주거 이동(사진 3줄) → 꼭 보는 장면 4곳 → 본편 보기(`scripts/cardnews/city.py`). 기준 `scripts/dosi/RUNBOOK.md`.

## 7. 카드뉴스 공통
1080×1350(4:5), 최대 10장, 흑백+황동, 매 장 쪽 번호·워드마크·사진 출처. 마지막 장 다음 행동 하나 + 투자 권유 아님. 올리는 곳: **네이버 클립 게시물**(수익화, 블로그 스티커) · **유튜브 이미지 게시물**(노출용) · 인스타(계정 생기면). 전달: 콘텐츠 폴더 `07_카드뉴스/`(도시·랭킹 쇼츠는 `카드뉴스/`) + 캡션 txt. 생성기 `scripts/cardnews/`(샘플 확인 후 구축). 기준 `docs/cardnews-plan.md`.

## 8. 사이트 공통 기능
- **홈 대문**: `home.js`가 `posts-data.js` 제목에서 숫자를 읽어 '이번 주 가장 큰 저평가'·청약 판정 카드 6개·미분양 권역별 1위를 자동으로 그린다(손으로 고치지 않는다). 카드마다 조감도.
- **썸네일**: 모든 글에 `posts/images/<slug>/thumb.jpg` + `posts-data.js`의 `thumb`. 청약은 공식 조감도·투시도, 랭킹은 1위 단지 사진. `python3 scripts/build_thumbs.py`.
- **계산기** `/calc/`: 청약 가점(주택공급규칙 별표1) · 당첨되면 필요한 돈(공고문 납부 조건 + 취득세) · 취득세(지방세법, 생애최초 감면, 조정대상지역 목록). 규정이 바뀌면 `calc/calc.js`와 확인 날짜를 고쳐 `scripts/calc/build_calc.py`로 다시 빌드. 단지 미리 고르기 `/calc/cash-plan.html?apt=<slug>`.
- **영상 넣기**: 어사이드가 업로드주소 파일에 주소를 적으면 `scripts/embed_video.py <slug> <주소…>`로 사이트 글에 '영상으로 보기'.

## 9. 어사이드 전달 — 구글 드라이브 'Aside 작업용 폴더'
GitHub에는 사이트 글·이미지만 올린다. 네이버 원고·영상·썸네일·카드뉴스·업로드 정보는 **드라이브**로, **원본 화질**로.
| 종류별 폴더 | 콘텐츠 폴더 이름 | 안의 파일 |
|---|---|---|
| 브동산 청약 | `YYYY-MM-DD 단지명 (slug)` | 00 읽어주세요 · 01 네이버원고+이미지 · 02 쇼츠1 분양가총정리 · 03 쇼츠2 가격퀴즈 · 04 쇼츠3 1분총정리(+썸네일) · 05 업로드 정보(교차링크 할 일 포함) · 06 업로드주소 · 07 카드뉴스 |
| 브동산 미분양 랭킹 | `YYYY-MM-DD 권역 미분양 랭킹 (slug)` | 읽어주세요 · 네이버원고+이미지 · 본편·쇼츠·썸네일 · 업로드 정보 · 카드뉴스 |
| 브동산 랭킹 쇼츠 | `YYYY-MM-DD 랭킹 쇼츠 3편` | 00 읽어주세요 · NN 영상·썸네일 · 카드뉴스 |
| 브동산 도시이야기 | `NN 도시명` | README(교차링크) · 네이버원고 · 본편·쇼츠 2 · 썸네일 · 설명 txt · credits · 업로드주소 · 카드뉴스 |
- 저장 방법: Paul 컴퓨터(`jhi`)가 연결돼 있으면 `G:\내 드라이브\Aside 작업용 폴더\…`에 `device_commit_files`로 직접(원본 화질). 아니면 Google Drive 커넥터(파일당 약 3.1MB 한도 — 큰 영상은 줄여 올리고 원본은 대화에 남김).
- 어사이드는 게시 후 폴더 이름 앞에 `[게시완료]`, 업로드주소 파일에 올린 주소를 적는다.

## 10. 배포·작업 규칙
- 커밋·push는 묻지 않고 진행. **push 직전 `git fetch` → 바뀌었으면 merge 후 등록 파일(posts-data.js·posts-manifest.json·sitemap.xml·feed.xml) 대조.** 회차당 push 한 번(Vercel 하루 100회 한도, 'rate limited'면 다시 push하지 않음). 배포 후 글·이미지 URL 200 확인.
- 커밋하지 않는 것: `~/.secrets/`, KB·지도 캐시(`scripts/beodongsan/kbcache.json`), `*-result.json`, `__pycache__`. 미완성 세트는 push하지 않는다.
- 사이트 글은 390px 폭에서 가로 넘침을 확인하고, 만든 이미지·정지 화면·카드는 직접 열어 글자 잘림·겹침을 본다.
- 오래 걸리는 작업은 작업 목록으로 진행 상황을 보이고, 끝나면 결론부터 짧게 보고한다.
